Disclaimer

It is called agent-first, but scripts decide

Subagents

Code that calls MCP tools with fixed arguments. No model chooses what to measure

Gate

The CLI gives the verdict with its exit code, and the rules pick the metric and, when they can, the cause

LLM

A single local model that writes the explanation. With no regression, it is not even asked

A gate has to give the same result for the same branch: what is not deterministic does not decide

What is not deterministic does not decide. The idea comes back in step 4.

Web Performance

What users perceive, measured

Loading

When do I see what I came for?

Stability

Does the page move while I use it?

Responsiveness

Does it react as soon as I touch something?

Each question has a metric, and each metric breaks down to show where the time goes

Three questions from the person using the page. Each one has its metric.

Core Web Vitals

Three metrics, three “good” thresholds

LCP

≤ 2.5 s

Largest Contentful Paint: when the largest element is painted

CLS

≤ 0.1

Cumulative Layout Shift: how much the content shifts

INP

≤ 200 ms

Interaction to Next Paint: how long it takes to respond to an interaction

The thresholds WebPerf Snippets returns with each measurement, Google’s for the 75th percentile

The three regressions of the workshop stay inside these thresholds. Keep that in mind for step 5.

LCP

LCP breaks down into four phases

TTFB
Load delay
Load time
Render delay
  • TTFB: until the first byte of the HTML arrives
  • Load delay: until the browser starts requesting the LCP resource
  • Load time: how long it takes to download
  • Render delay: from when it arrives until it is painted

Only LCP for now. INP and CLS come during the wait of step 3.

INP and LoAF

An interaction has three phases

Input delay

The main thread is busy and the event waits

Processing

The event handlers run

Presentation delay

Until the browser paints the next frame

Long Animation Frames (LoAF): name the script that blocks and what invokes it. A trace of the click names the function

The three phases of an interaction. The long animation frames name the script; the trace of the click, the function.

CLS

Not every shift counts

They count

The ones the user did not cause: a banner that comes in without reserved space, a font that changes size when it loads

They do not count

The ones right after an interaction, like a panel that opens on a click

To fix it, the number is not enough: you need to know which nodes move

Shifts that follow an interaction do not count.

Step 4 · What you take away

A verdict you can defend

  • The rules decide and the LLM explains. If they contradict each other, the rules win and the report says so
  • The statistics, the attribution and the facts come first. The sentence of the LLM is the last thing to arrive
  • With lite, the same verdict and the same findings: the explanation is asked for elsewhere, with the handoff

To think about: in your team, who would read this report, and what do they need to see to trust it?

Ask: what would show in the report if the LLM said the opposite of the rules?

Step 5

The gate in the CI of every pull request

for branch in pr-lcp-hero-lazy pr-cls-promo-banner pr-loaf-cart-handler pr-noop-refactor; do
  CANDIDATE=$branch docker compose run --rm -e OUT=/out/ci/$branch ci
  echo "$branch: exit $?"
done

Three exits, and one more answer

What you take away

Five ideas for your platform

  • The rules decide, the LLM explains
  • Compare with the base version, not with a threshold
  • Measure one at a time, and alternate the two versions
  • A gate has to say when the data is not enough
  • Not everything has to be an MCP
