Core Web Vitals

Tres métricas, tres umbrales de “good”

LCP

≤ 2,5 s

Largest Contentful Paint: cuándo se pinta el elemento más grande

CLS

≤ 0,1

Cumulative Layout Shift: cuánto se desplaza el contenido

INP

≤ 200 ms

Interaction to Next Paint: cuánto tarda en responder a una interacción

Los umbrales que devuelve WebPerf Snippets en cada medida, los de Google para el percentil 75

LCP

El LCP se descompone en cuatro fases

TTFB
Retraso de carga
Tiempo de carga
Retraso de render
  • TTFB: hasta que llega el primer byte del HTML
  • Retraso de carga: hasta que el navegador empieza a pedir el recurso del LCP
  • Tiempo de carga: lo que tarda en descargarse
  • Retraso de render: desde que llega hasta que se pinta

CLS

No todos los desplazamientos cuentan

Cuentan

Los que la persona no ha provocado: un banner que entra sin espacio reservado, una fuente que cambia de tamaño al cargar

No cuentan

Los que llegan justo después de una interacción, como un panel que se abre al hacer click

Para arreglarlo no basta con el número: hay que saber qué nodos se mueven

INP y LoAF

Una interacción tiene tres fases

Retraso de entrada

El hilo principal está ocupado y el evento espera

Procesamiento

Corren los handlers del evento

Retraso de presentación

Hasta que el navegador pinta el siguiente frame

Long Animation Frames (LoAF): nombran el script que bloquea y quién lo invoca. Un trace del click nombra la función

Los subagentes

Cada uno mide una cosa, ninguno decide

SubagenteQué hace
NavigatorRecorre la tienda paso a paso y comprueba que cada recorrido termina

CLSLos desplazamientos de cada recorrido y los nodos que se mueven

Antes de empezar

Tu rama, desde el inicio del taller

# con las imágenes descargadas y el preflight en verde
git fetch origin workshop --tags
git switch -c taller workshop-start
docker compose up -d

Con 8 GB, antepón COMPOSE_PROFILES=lite a cada comando de docker compose. Cada paso tiene su guía en la web del taller

La primera llamada a un MCP

Escribes

Paso 4

El Judge

Escribes

  • lcpFacts, clsFacts e inpFacts en findings.ts
  • Los hechos que respaldan la explicación

Sin MCP

  • Reglas sobre los JSON de los subagentes
  • El LLM no ve estos hechos: su prompt es el del benchmark
docker compose run --rm agents npm run check -- step-04

Paso 5

El gate en el CI de cada pull request

for branch in pr-lcp-hero-lazy pr-cls-promo-banner pr-loaf-cart-handler pr-noop-refactor; do
  CANDIDATE=$branch docker compose run --rm -e OUT=/out/ci/$branch ci
  echo "$branch: exit $?"
done

Tres fallos y un pass. Lee el report.md de cada rama: el veredicto, la explicación y lo que la respalda

Si te descuelgas

Cada paso tiene su solución

git checkout step-02-solution -- agents/src

Los tags step-01-solution a step-04-solution traen el código del paso resuelto. El paso 5 funciona aunque no hayas escrito nada
